# callstack-diff (csd)

A local Bun + TypeScript tool that renders and diffs **static** call-stack trees
for JS/TS using the [Oxc](https://oxc.rs) parser (`oxc-parser`). It exists to
make markdown plans and refactors readable at a glance: a shallow, flat tree is
usually healthy; a deep or ballooning one is a slop signal.

## Commands

```
csd <entry> [paths...] [options]        # render a call-stack tree
csd diff <entry> [paths...] --from REF  # diff the tree between two revisions
```

`<entry>` is `name`, `Class.method`, or `file.ts#name`. Without `paths`, csd
scans `**/*.{ts,tsx,mts,cts,js,jsx,mjs,cjs}` under `--root` (default: cwd),
ignoring `node_modules`, `dist`, `build`, and `.git`.

Key options: `--depth N` (default 6), `--no-branches` (drop if/else/switch
grouping), `--args` (include raw call arguments), `--theme default|libretto|none`,
and for `diff` the `--from <ref>` / `--to <ref>` git revisions (`--to` defaults
to the working tree).

## How it works

1. `project.ts` parses each file with `oxc-parser` and indexes function
   declarations, arrow/function consts, and class members by bare name and by
   `Class.method`.
2. `tree.ts` walks the entry body in source order, extracts the outermost
   call/`new` expressions per statement, groups `if/else/switch` into branch
   nodes, and recurses into resolved callee bodies (depth- and cycle-guarded).
3. `diff.ts` aligns two trees' children by label with an LCS and marks nodes
   `+`/`-`/context.
4. `render.ts` prints the box-drawing tree; `git.ts` materializes a ref with
   `git archive` for the `diff` command.

## Resolution is a heuristic

Call resolution is name-based and intentionally simple: it does not do full type
resolution, so dynamic dispatch, re-exports, and same-named symbols across files
resolve to the first match. Bare `foo()` prefers a free function over a class
member. Calls passed as arguments are not expanded as siblings; the resolved
callee body is what gets expanded. Treat the output as a readable approximation,
not a sound call graph.

## Build & packaging

- Runs sources directly on Bun (no bundle step); `default.nix` ships `src/` plus
  the bun2nix-provided `node_modules` and wraps `bun run src/cli.ts` as `csd`.
- Dependencies, including the native `@oxc-parser/binding-*` packages, are pinned
  in `bun.nix` (generated by bun2nix) and fetched via `fetchBunDeps`.

## Updating dependencies

```bash
bun install                 # refresh bun.lock
nix run github:nix-community/bun2nix -- -l ./bun.lock -o ./bun.nix
nix build .#callstack-diff
```

Keep `@types/bun` pinned to a concrete version; `latest` makes bun2nix emit a
non-reproducible lockfile warning.
