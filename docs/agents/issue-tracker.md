# Issue tracker: Beads

Issues and specs live in Beads. The committed source of truth is
`.beads/issues.jsonl`; local SQLite databases, locks, recovery files, and
history backups are regenerated by `br` and ignored by Git. Run `br` from the
repository root. `bd` is retired in this repository and must not be used.

## Common commands

```bash
br ready
br show <issue-id>
br create "Title" --type task --priority 2
br update <issue-id> --add-label <label>
br sync --import-only
br sync --flush-only
br close <issue-id> --reason "<reason>"
```

Use `br show <issue-id>` as the live check before acting or claiming an issue.
Close only after every acceptance criterion has fresh evidence and the work is
landed. Keep downstream patch beads open until the patch is removed and the
affected package is verified without it.
