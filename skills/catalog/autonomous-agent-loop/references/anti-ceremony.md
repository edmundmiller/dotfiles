# Just say no to process porn and ceremony

Deliver the requested outcome with evidence. Keep process that reduces mistakes
or supports a requested handoff. This skill does not authorize publication or
override safety checks or a multi-stakeholder process the user requested.

Use `via-negativa` for product/plan subtraction, `deslop` for post-correct code
review, and the [parent workflow](../SKILL.md) when durable goal management is needed.

## Check the outcome

- Verify the requested behavior with a run, reproduction, or UI check. Plans,
  scaffolding, status reports, and green checks that miss the behavior are not proof.
- Never change tests, fixtures, snapshots, or verifiers just to make them pass.
  Fix the product, or establish that the check is wrong before correcting it.
- Report incomplete work honestly. Do not call it done, disguise it as an MVP,
  or claim a blocker when an authorized next action is available.
- Skip repeated plans, unnecessary docs, and multi-agent reviews for tiny diffs.
  Read what the change needs; parallelize only independent work when authorized.
- Remove temporary scaffolding you added. Preserve unrelated work.

## When work stalls

Privately identify the unmet outcome, the observable result that would prove it,
and the smallest authorized edit or command toward it. Do that next action;
do not turn this diagnostic into another worksheet or status report. Ask only
for intent, authority, or tradeoffs that repository evidence cannot resolve.

For example, a rename needs a focused check, not three reviewers. A failing UI
interaction needs reproduction and a fix, not another architecture plan.
Before claiming completion, inspect the behavior evidence and report the actual
delivery state and any limitation. No mandatory output template is required.
