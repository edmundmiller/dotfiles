# ghui overlay instructions

Upstream `kitlangton/ghui` exposes only a devShell from its flake, so this
overlay builds the package itself from the `ghui` flake input's source and
surfaces it as `pkgs.my.ghui` for `modules/shell/git/default.nix`.

Because the overlay needs `inputs`, it is applied explicitly in `flake.nix`
(`overlays.ghui = import ./overlays/ghui inputs;`) rather than through the
`mapModules ./overlays import` auto-import used by bare `final: prev:` overlays.

## Source pins

The `flake.nix` ghui input rev and `package-harness.json` `ref` must match.

Currently pinned to `kcosr/ghui` at `855649490c25ac5d561e1ded987d72af7b07d3fa`,
the head of PR #43 (diff hunk navigation and copy: `{`/`}` navigation, `y`/`Y`
copy). Repin to `kitlangton/ghui` once that PR merges.

Validate a new pin from a checkout of that rev with ghui's own checks:
`bun run typecheck` and the targeted `bun test` commands in
`package-harness.json`.

## bun.nix

`bun.nix` is generated by `bun2nix` from a checkout of the pinned rev and is
copied into the source tree when building, because it references the
`@ghui/keymap` workspace package by a path relative to itself. Regenerate it
whenever the pin touches `bun.lock`:

```sh
bun2nix -o overlays/ghui/bun.nix
```
