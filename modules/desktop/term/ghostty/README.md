# Ghostty Module

Ghostty terminal emulator configuration for nix-darwin.

## Installation

Enable in host config:

```nix
modules.desktop.term.ghostty.enable = true;
```

On macOS, Ghostty is installed as the Nix `ghostty-bin` app bundle.
On Linux, the upstream Ghostty flake package is used.

## What This Module Provides

- **Config generation:** Main config, keybindings, and behavior.conf with PATH injection
- **macOS Terminal.app aesthetics:** Creates a Terminal profile from the same Stylix font/colors used for the host terminal theme
- **Extensible keybindings:** Other modules can add keybindings via `keybindingFiles` or `keybindingsInit`
- **PATH injection:** Ensures nix-managed commands (like Herdr/tmux) are available at startup
- **macOS legacy config cleanup:** Removes `~/Library/Application Support/com.mitchellh.ghostty/config` when present, preventing old autogenerated templates from shadowing `~/.config/ghostty/config`

## Options

### `modules.desktop.term.ghostty.enable`

Enable the Ghostty module.

### `modules.desktop.term.ghostty.keybindingFiles`

List of keybinding files to concatenate into `keybindings.conf`.

Default: `[ "${configDir}/ghostty/keybindings.conf" ]`

Example (from another module):

```nix
modules.desktop.term.ghostty.keybindingFiles = [
  "${configDir}/ghostty/my-keybindings.conf"
];
```

### `modules.desktop.term.ghostty.keybindingsInit`

Inline keybinding text appended to `keybindings.conf`.

Example:

```nix
modules.desktop.term.ghostty.keybindingsInit = ''
  keybind = ctrl+shift+t=new_tab
'';
```

### `modules.desktop.term.ghostty.configInit`

Inline config text appended to the main config file.

Example:

```nix
modules.desktop.term.ghostty.configInit = ''
  font-size = 14
'';
```

### `modules.desktop.term.ghostty.macosTerminalProfileName`

Name of the generated Terminal.app profile. Default: `Ghostty Match`.

On Darwin hosts with Stylix enabled, activation creates/updates this profile and
sets it as Terminal.app's startup/default profile. It mirrors the host Stylix
monospace font, terminal font size, background, foreground, bold, cursor, and
color settings so Terminal opens with the same basic aesthetic as Ghostty.

## Extending Keybindings

Other modules (like `pi`) can add keybindings:

```nix
# Using keybindingFiles (recommended for separate files)
modules.desktop.term.ghostty.keybindingFiles = mkIf ghosttyCfg.enable [
  "${configDir}/ghostty/pi-keybindings.conf"
];

# Using keybindingsInit (for inline additions)
modules.desktop.term.ghostty.keybindingsInit = mkIf ghosttyCfg.enable ''
  keybind = alt+backspace=text:\x1b\x7f
'';
```

Use `mkBefore` to prepend or `mkAfter` to append relative to other modules.

## Startup Ownership

Ghostty opens a plain shell on macOS. When Herdr is enabled with
`modules.shell.herdr.backend = "native"`, Ghostty also opens a plain shell on
Linux and uses terminal tab bindings instead of tmux prefix bindings.

Native Herdr is a separate app installed by the official installer. Its signed
bundle, `herdr-app` and `hc` are installer-owned. Its configuration lives under
`~/.config/herdr-app`, independently of Ghostty. This module does not package or
modify the native app. The Herdr backend defaults to `native` on Darwin and
`legacy` on Linux.

With the `legacy` backend on Darwin, this module installs
`packages/herdr-ghostty`. It provides `Herdr Ghostty.app`, a locally signed
Ghostty copy with its own bundle identifier. Its private config shares Ghostty
settings but disables the global quick-terminal shortcut and launches
`~/.config/tmux/open-herdr.sh`. Ordinary Ghostty keeps Cmd+grave. Nix owns updates
to Ghostty and this legacy copy, not to native Herdr.

On Linux with the `legacy` backend, startup selects legacy Herdr when enabled,
otherwise jmux if enabled, otherwise tmux. The legacy Herdr launcher must not
fall back to tmux. That fallback can start Herdr inside tmux and recreate a
Ghostty to Herdr to tmux to Herdr loop.

## PATH Injection

Ghostty's `command` directive runs before shell profiles load (`--noprofile --norc`).
This module injects PATH into `behavior.conf` so nix-managed startup commands are found:

```
env=PATH=/Users/<user>/.nix-profile/bin:/etc/profiles/per-user/<user>/bin:...
```

## Troubleshooting

### Legacy Herdr/tmux not launched on Linux

Native mode and ordinary macOS Ghostty intentionally open a plain shell.
For legacy Linux startup:

1. Verify `~/.config/ghostty/behavior.conf` contains `env=PATH=...` and the expected startup command. Enabled legacy Herdr selects `~/.config/tmux/open-herdr.sh`.
2. Check PATH includes `/etc/profiles/per-user/<username>/bin` and your user bins.
3. After an authorized `hey rebuild`, fully quit and reopen Ghostty.

On macOS, also verify that
`~/Library/Application Support/com.mitchellh.ghostty/config` is absent. It can
shadow the XDG config for GUI launches. Activation removes this old config.

### Keybindings not working

1. Check `~/.config/ghostty/keybindings.conf` was generated correctly
2. Verify no syntax errors in keybinding files
3. **Fully restart Ghostty** (Cmd+Q → reopen) - keybindings require full restart

### Keybindings not updating after config reload

Ghostty caches keybindings at startup for performance. While most config changes
(colors, fonts, etc.) apply with `Ctrl+Shift+,` or `ghostty +reload-config`,
**keybindings are only parsed at launch**. You must fully quit and restart Ghostty
for keybinding changes to take effect.

### SSH shows wrong TERM

The module sets `TERM=xterm-256color` when SSH is detected (ghostty terminfo isn't widely available).
